### FR-045 — FDR: Forced Displacement to Habitable Zone

**Status:** ✅ Implemented

**Problem:** The most habitable world in a system could end up in the Hot, Cold, or Outer zones simply because the random placement algorithm put it there. For TTRPG purposes, the mainworld (the world players interact with) should ideally be in the habitable zone.

**Solution:** After competitive mainworld selection, if the `forceHZRelocation` toggle is enabled, check whether the winner is in the Conservative zone. If not:
1. Assign it a new random AU within `zones.conservative.min … zones.conservative.max`.
2. Compute Hill-sphere conflicts against every L1 body using the existing `4.0 × max(r_H1, r_H2)` rule from FR-042.
3. Eject all conflicting occupants (`wasEjected = true`, `ejectionReason = 'saturation'`, moved to `ejectedBodies`).
4. If the winner is a moon, promote it to an independent L1 body:
   - Remove from `moons` array.
   - Add to `dwarfs` or `terrestrials` array based on type.
   - Clear `parentId`, `moonOrbitAU`, `parentDistanceAU`.
   - Set `level = 1`, `orbitLevel = 1`, `wasPromotedFromMoon = true`.
5. Re-run the full 10-step habitability waterfall so the body's score, temperature, hazard, and biosphere reflect its new zone.

**UI toggle:** Added "Force mainworld to Habitable Zone" checkbox in the **System Targets** section of the generator dashboard. Default is **off** so existing behaviour is preserved.

**Log tracking:**
- `mainworldSelectionLog.fdrApplied` — boolean, true when relocation occurred.
- `mainworldSelectionLog.fdrEjectedIds` — array of body IDs ejected to make room.
- `PlanetaryBody.wasPromotedFromMoon` — boolean flag for promoted moons.
